# 首次配置

这个 skill **只用于 Java 后端面试**，资料**固定用 JavaGuide**，题目路径固定为 [syllabus.md](syllabus.md) 里的标准题库。配置要确定的只有三件事：谁在学（简历、项目、侧重点）、学哪些（范围）、怎么学（追问深度、复习间隔）。

目标是让新用户尽快见到第一道题，不要一项一项来回问很多轮。

**第一轮**：先问笔记放哪（默认是当前目录下的 `笔记/`），然后把下面全部配置项连同默认值一次性列给用户，例如：

> 必填：① JavaGuide 本地路径（还没 clone 的话先执行 `git clone https://github.com/Snailclimb/JavaGuide.git`） ② 简历（路径或粘贴） ③ 追问深度（三档说明见下，推荐「面试高频」）
> 选填（不答就用默认值）：项目代码或文档（默认：只用简历描述）、个人侧重点（默认：无）、范围调整（默认：核心模块全学，可选模块不学）、复习间隔（默认：第 1、3、7 天）、是否公开（默认：否）、语言（默认：跟随你）

追问深度的三档说明必须在这一轮完整讲给用户。

**第二轮**：读完简历，列出从**项目经历 bullet** 里识别到的技术点和亮点；技能栏只简单列一下，不做分析。再列出核心模块和可选模块清单，让用户删掉不要的，加上想学的可选模块。**这一轮不要定任何题的优先级**：还没审查代码，不知道简历里写的东西是不是真的实现了。优先级等第 1 步的项目画像完成后，在第 2 步统一定。

用户回答零散的话，只追问还缺的必填项。全部确认后，把结果写进笔记目录下的 `学习配置.md`（格式见文末），并复述一遍。以后用户可以随时改任何一项。

下面是每一项的细节。

## 1. JavaGuide 本地路径（必填）

问：JavaGuide 仓库 clone 在哪？

- 还没有的话，让用户先执行：

  ```bash
  git clone https://github.com/Snailclimb/JavaGuide.git
  ```

  仓库比较大，提醒用户放在空间充足的磁盘。
- 拿到路径后，检查 `{路径}/docs/` 是否存在，并抽查题库里的一两个文件（比如 `docs/database/mysql/mysql-index.md`）。不存在就请用户确认路径，或者 `git pull` 更新。
- 能读本地文件的环境（如 Claude Code）：出题时给出完整的本地文件路径，指到小节标题；纠错时先读原文核对，再下结论。
- 不能读本地文件的环境（如网页版 ChatGPT）：仍然请用户 clone，自己按路径打开阅读；需要核对原文时，请用户上传或粘贴对应文件。

## 2. 简历（必填）

问：简历在哪？可以给文件路径，也可以直接粘贴文本。

- 没有简历时，告诉用户这套方法的优势会少一大半，建议先写一版；用户坚持的话，跳过 📄 阶段，直接按题库的高频题推进。
- **重点看项目经历的 bullet**，这是面试官追问的主线。技能栏只当弱信号：很多人的技能栏写得又杂又泛，单凭技能栏不升优先级，只在它和项目 bullet 或代码对得上时才算数。
- 读完简历后，列出从 bullet 里识别到的技术点和亮点，让用户确认有没有漏、有没有不想被问的（比如写了但不熟、准备删掉的）。

## 3. 项目（选填）

问：简历里的项目代码或文档在哪？可以是仓库路径、文档、或者一段描述。有现成的项目面试题库也一起给。

- 能读代码的环境里，出项目题之前要先看代码。
- 只有描述时，告诉用户：涉及项目细节的结论需要你贴代码来核对，否则只能按通用做法讲。

## 4. 个人侧重点（选填）

问：除了简历和项目，你还有没有自己想侧重的？例如：
- 目标公司类型（大厂偏底层原理，中小厂偏项目和实用）
- 自己知道薄弱、想优先补的模块
- 面试时间（越近越要先保 P0）

侧重点会影响优先级：想优先补的模块里的高频题可以升为 P0；面试临近时，低频题可以整体推后。也可以给某个模块单独设追问深度。

## 5. 范围（选填）

默认：题库里的**核心模块全学**，**可选模块不学**。

- 先把模块清单列给用户，让用户删掉不要的核心模块、加上想学的可选模块。也可以删到单道题。
- 有没有只需要了解浅层的内容？标成 P2。可以是整个模块，也可以是单个技术点。
- 简历里写了的技术，所在模块不在范围内时（比如简历写了 Docker，但工具模块默认不学），要提醒用户："这项写在简历上，面试大概率会问"。用户同意的话，把对应的题加进来，每项只准备 3～5 个常见问题，不深挖。

## 6. 追问深度（必填）

**先把下面三档的后果讲给用户听，再推荐「面试高频」，让用户自己选。**

| 档位 | 怎么追问 | 好处 | 代价 |
|---|---|---|---|
| **面试高频（推荐）** | 每题 1～2 个追问，只问面试真会问的高频链路；冷门细节不追，最多在口述版里一句带过；项目只深挖简历上写了的亮点 | 进度快，学的都是面试会问的，不容易被细节拖垮 | 遇到喜欢抠底层的面试官，个别深问题可能接不住 |
| 标准 | 每题 2～3 层追问，包含一些原理性的"为什么" | 理解更扎实，能应付大部分深挖 | 每题耗时明显增加，整体进度慢 |
| 深挖 | 3 层以上，追到源码、实现细节、边界条件 | 真正吃透，适合目标岗位技术要求很高的人 | 很慢，容易陷进冷门细节，偏离"把面试内容覆盖完" |

推荐理由（可以原样告诉用户）：这套方法的作者一开始用的是 2～3 层追问，后来发现追问太细、离"掌握面试内容"越来越远，于是改成每题 1～2 个高频追问，效果更好。先用高频档把范围全部覆盖，之后再对重点模块单独切到更深的档位，比一开始就深挖更划算。

用户可以随时改档位，也可以对单个模块设不同档位。

## 7. 复习间隔（选填）

默认第 1、3、7 天闭卷复述。离面试很近时可以改成第 1、2、4 天。

## 8. 笔记（选填）

- **笔记目录**：默认是当前目录下的 `笔记/`。
- **是否公开**：公开的话，引用 JavaGuide 只写出处和链接，不整段照搬（JavaGuide 是 Apache 2.0 许可）。
- **语言**：笔记和对话用什么语言，默认中文。

## 配置文件格式

```markdown
# 学习配置

- 方向：Java 后端（固定）
- JavaGuide 本地路径：
- 简历：（路径，或"见下方粘贴"）
- 项目：（路径 / 文档 / 描述）
- 项目题库：（可选）
- 个人侧重点：
- 删掉的核心模块或题目：
- 加上的可选模块或题目：
- 浅层（P2）：
- 追问深度：面试高频 / 标准 / 深挖（单个模块例外：……）
- 复习间隔：1 / 3 / 7 天
- 笔记目录：
- 是否公开：
- 语言：
- 配置日期：

## 简历中识别出的技术点和亮点
（列表，用户确认过的版本）

## 修改记录
（日期 + 改了什么）
```
